# DunderCode Engineering Knowledge Graph (DEKG)

The DunderCode Engineering Knowledge Graph (DEKG) is the semantic knowledge model of the DunderCode Engineering System (DESys).

It defines how engineering assets are connected through explicit semantic relationships, enabling consistent navigation, traceability, validation, reuse, and AI-assisted engineering.

Rather than treating engineering documents as isolated artifacts, the DEKG organizes engineering knowledge as an interconnected graph.

Every engineering asset becomes part of a continuously evolving engineering knowledge ecosystem.

---

# Purpose

The purpose of the DEKG is to provide the semantic foundation of DESys.

It enables engineering knowledge to be organized according to meaning rather than physical location, allowing engineers and AI agents to discover relationships that would otherwise remain implicit.

The DEKG transforms documentation into an interconnected engineering platform.

---

# What is the DEKG?

The DEKG is a semantic graph composed of engineering assets and the relationships between them.

Within the graph:

- Engineering assets become nodes.
- Semantic relationships become edges.
- Metadata enriches every node.
- Navigation emerges from semantic connectivity.

This model enables engineering knowledge to evolve as an integrated system rather than a collection of independent documents.

---

# Core Concepts

The DEKG is built upon several architectural components.

| Component | Responsibility |
|-----------|----------------|
| Metadata | Describes engineering assets. |
| Node Types | Defines categories of engineering knowledge. |
| Relationships | Connects engineering assets semantically. |
| Knowledge Map | Provides navigational structure. |
| DESys Architecture | Defines the overall platform architecture. |

Each component is documented independently while contributing to the same semantic architecture.
