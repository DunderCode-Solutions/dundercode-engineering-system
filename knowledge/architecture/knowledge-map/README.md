# Knowledge Map

The Knowledge Map defines how engineering knowledge is organized and navigated throughout the DunderCode Engineering System (DESys).

It provides the conceptual navigation model that enables engineers, technical writers, automation tools, and AI agents to discover engineering assets efficiently and consistently.

Rather than describing the internal architecture of the platform, the Knowledge Map focuses on how knowledge is explored and understood.

It serves as the primary navigation guide for the engineering ecosystem.

---

# Purpose

The purpose of the Knowledge Map is to provide a clear and intuitive navigation model for DESys.

Engineering knowledge should be easy to discover, understand, and connect regardless of its location within the platform.

The Knowledge Map ensures that every engineering asset can be reached through a logical and predictable navigation path.

---

# Navigation Model

DESys follows a hierarchical navigation model.

Engineering knowledge is progressively organized from high-level concepts to specialized engineering assets.

```text
Platform
    │
    ▼
Layer
    │
    ▼
Domain
    │
    ▼
Specification
    │
    ▼
Engineering Asset
```

This model allows readers to move naturally from broad concepts to detailed engineering guidance.

---

# Knowledge Hierarchy

The engineering platform is organized into interconnected architectural layers.

```text
DESys Platform
│
├── Foundation Layer
│
├── Knowledge Layer
│
├── Engineering Layer
│
└── Delivery Layer
```

Each layer contains domains that specialize in a specific engineering capability.

Domains contain specifications.

Specifications reference engineering assets.

Engineering assets contribute back to the overall knowledge ecosystem.

# Finding Engineering Assets

Engineering assets can be discovered through multiple complementary paths.

Examples include:

- Navigating architectural layers.
- Exploring specialized domains.
- Following semantic relationships.
- Searching by canonical identifier.
- Browsing engineering categories.
- Traversing the DunderCode Engineering Knowledge Graph (DEKG).

The navigation model is intentionally redundant, allowing users to discover knowledge from different perspectives.

---

# Relationship with the DEKG

The Knowledge Map and the DEKG complement one another.

The Knowledge Map provides the human-oriented navigation structure.

The DEKG provides the semantic relationship model that connects engineering assets beyond the hierarchical structure.

Together they enable both intuitive exploration and semantic discovery.

```text
Knowledge Map
        │
Human Navigation
        │
        ▼
Engineering Assets
        ▲
Semantic Relationships
        │
DEKG
```
