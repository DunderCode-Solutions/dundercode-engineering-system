# DSK-2024 | Domain Traceability

# 1. Purpose

This skill defines how AI agents establish, maintain and validate traceability across all domain artifacts within the DunderCode Engineering System (DESys).

Domain Traceability ensures that every domain concept can be traced from its business origin through the complete domain model and into architecture, implementation and verification artifacts.

Beyond traditional traceability matrices, DESys represents domain relationships as a Knowledge Graph, enabling AI agents to navigate, analyze and reason over engineering knowledge through explicit semantic connections.

# 10. Knowledge Graph

DESys represents traceability as a semantic Knowledge Graph.

Each engineering artifact becomes a graph node.

Relationships between artifacts become typed graph edges.

Example:

Business Goal
    ↓
Business Capability
    ↓
Business Process
    ↓
Business Rule
    ↓
Domain Event
    ↓
Aggregate
    ↓
Repository

The Knowledge Graph enables:

- semantic navigation;
- dependency analysis;
- impact analysis;
- engineering reasoning;
- AI context retrieval;
- document discovery;
- architecture exploration.

This graph serves as the canonical navigation structure for DESys AI agents.

---

# 11. Graph Relationship Types

DESys defines a canonical set of semantic relationships used by the Knowledge Graph.

Every edge generated by `desys-indexer` MUST use one of these relationship types.

| Relationship | Meaning |
|--------------|---------|
| derives_from | Artifact originates from another artifact. |
| depends_on | Artifact requires another artifact to exist or function. |
| implements | Artifact realizes the behavior defined by another artifact. |
| references | Artifact explicitly references another artifact. |
| validates | Artifact validates another artifact or business concept. |
| triggers | Artifact causes another artifact or process to occur. |
| produces | Artifact generates another artifact. |
| consumes | Artifact uses another artifact as input. |
| owns | Artifact is responsible for another artifact. |
| belongs_to | Artifact is contained within another artifact. |
| extends | Artifact extends the behavior of another artifact. |
| specializes | Artifact refines a more generic artifact. |
| realizes | Artifact materializes an abstract business concept. |

Custom relationship types SHOULD be avoided unless formally introduced through Architecture Governance.

# 12. Traceability Structure

Each traceability relationship should include:

- Source Artifact
- Target Artifact
- Semantic Relationship Type
- Cardinality
- Confidence
- Dependency Direction
- Impact Level
- Business Justification
- Traceability Reference

# 13. Validation

Before completion the skill verifies:

- all major domain artifacts are connected;
- the Knowledge Graph contains no orphan nodes;
- every semantic relationship is valid;
- every node has an explicit artifact type;
- dependency directions are consistent;
- impact paths are complete;
- graph navigation is deterministic;
- engineering traceability is preserved.
