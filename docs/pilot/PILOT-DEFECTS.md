# DESys v0.1 Pilot Defects

## PILOT-A-005 - Source File Without Terminal Newline Rejected

Severity: High
Status: Fixed and verified in rebuilt candidate
Owner: DESys maintainer
Disposition: Fixed before `v0.1.0-alpha.1`
Detected during: `PKG-006` cold/warm quality-gate measurement

### Environment

- Pilot: Pilot A, new project
- DESys candidate: `09aaec62fc5183ed19f30d13b73f39301812bd8d`
- Tool source: repository-relative wheel
- `uv`: 0.12.3
- Host: Linux x86_64

### Reproduction

`tools/desys-source.txt` contained exactly one valid wheel path without a
terminal newline. Running:

```bash
bash scripts/desys-docs-quality.sh
```

returned:

```text
ERROR: DESys source file must contain exactly one non-empty line.
```

### Root Cause

Bash `read` assigns the final unterminated line but returns a non-zero status at
EOF. The generated script treated that status as an empty or invalid source and
discarded the assigned value.

### Correction

The generated script now accepts exactly one non-empty source line with or
without a terminal newline. It continues to reject empty and multiple-line
source files before invoking `uvx`.

### Regression Coverage

- one valid source line with terminal newline;
- one valid source line without terminal newline;
- multiple source lines;
- malformed or mutable source values.

### Release Impact

The affected candidate was excluded from final packaging evidence. Candidate
`75e7d2fb1ec35623df04d1862060589712a440d7` passed all packaging scenarios in
the final Pilot A cycle.

## PILOT-B-001 - Push Workflow Excludes Nonstandard Default Branch

Severity: High
Status: Fixed and verified in rebuilt candidate
Owner: DESys maintainer
Disposition: Fixed before `v0.1.0-alpha.1`
Detected during: Pilot B remote CI preflight

### Environment

- Pilot: Pilot B, existing project
- Project default branch: `develop`
- DESys candidate: `30445a280e1210a158d93bf33e322258dbdf7167`
- Generated workflow: `.github/workflows/desys-docs-quality.yml`

### Reproduction

Initialize a repository whose default branch is neither `main` nor `master`.
The generated workflow contains:

```yaml
push:
  branches:
    - main
    - master
```

Committing and pushing the scaffold to the actual default branch does not
trigger the documentation job.

### Root Cause

The workflow template assumed two conventional default-branch names instead of
remaining independent from consumer branch policy.

### Correction

The generated workflow now accepts push events on every branch. Pull-request
and manual-dispatch behavior is unchanged. This avoids encoding consumer branch
governance into DESys.

### Regression Coverage

The initializer test now asserts that the generated workflow contains the push
event without a branch-name filter.

### Release Impact

The correction first passed in candidate
`d959114699b19a0cb1aa9b4523bceeac6e8fcf0f` and remains verified in final
candidate `75e7d2fb1ec35623df04d1862060589712a440d7`. Pilot B final run
`32314796582` passed automatically on default branch `develop`.

## PILOT-A-006 - Generated Ignore Block Was Unclear

Severity: Low
Status: Fixed and verified in rebuilt candidate
Owner: DESys maintainer
Disposition: Fix before `v0.1.0-alpha.1`
Detected during: Pilot A usability review

### Expected Behavior

The managed `.gitignore` block should explain why `docs/generated/` is ignored
and how it is recreated.

### Actual Behavior

The block contained only markers and `/docs/generated/`, so the tester reported
the file as the unclear generated integration element.

### Correction

The block now states that the directory is regenerated by
`scripts/desys-docs-quality.sh` and must not be committed.

### Evidence And Release Impact

Regression coverage asserts that the explanation appears exactly once and that
second-run idempotency remains intact. Final candidate `75e7d2f...` passed both
pilots and their remote workflows.

## PILOT-A-007 - Agent Prose Did Not Match Language Metadata

Severity: Medium
Status: Fixed and verified in rebuilt candidate
Owner: DESys maintainer
Disposition: Fix before `v0.1.0-alpha.1`
Detected during: Pilot A usability review

### Expected Behavior

Metadata schema v1 requires `language: en`; source document prose must therefore
be English unless the schema and metadata are deliberately changed in a future
version.

### Actual Behavior

During an earlier agent-assisted document generation, filenames and metadata
were English while ADR, PRD, and RFC prose was written in Portuguese. Metadata
validation could not infer the prose language and accepted the mismatch.

### Correction

Generated `AGENTS.md` now states that schema v1 source prose must be English,
prohibits labeling non-English content as `en`, and requires clarification when
another content language is requested.

### Evidence And Release Impact

Regression coverage asserts the language instruction. A fresh agent session on
final candidate `75e7d2f...` refused Portuguese prose labeled as `language: en`,
changed no file, requested clarification, and passed the unchanged quality gate.
